# FOUR AXES
### A portrait of asymmetric labour / field score 001

**The graph is the instrument. The work is the score.**

This project begins with a screenshot of GitHub's four-arm *Activity overview* on **7 November 2026**. Its visible proportions were **72% commits / 27% pull requests / 1% issues / 0% code reviews**. This is a deliberately dated snapshot, **not** a live API response, nor a raw count of events.

GitHub calls these *contributions*. The four dimensions are real but reductive: they cannot tell whether a piece of code was generous, difficult, elegant, fragile, or worth maintaining. The vanishing review axis is a beautiful absence: GitHub can count review submissions but not the hours spent studying someone else's work.

The first image is a frozen diagram of these four proportions. The second piece is an offline instrument: four editable channels draw a layered radial shape and modulate **four synthesized oscillators**. A disproportionate history becomes a disproportionate sound.

## Look and listen

- [FOUR AXES / static score](../../assets/four-axes.svg) (SVG, embedded in the GitHub profile)
- [FOUR AXES / interactive instrument](index.html) (download/open the HTML locally, or serve this folder with `python3 -m http.server 8000` and visit `http://localhost:8000`)
- The **play** button is required to start audio. Nothing plays automatically.
- Adjust each channel and export the current visual as an SVG.
- Reset restores the 72/27/1/0 screenshot proportions.

The instruments require **no dependencies, accounts, tokens, external network calls or supplied music**. Sonification uses Web Audio oscillators and a conservative output gain. This is an original procedural composition, not playback of any copyrighted song.

## What is and is not manipulated

The **actual GitHub Activity overview** is generated by GitHub. Neither this SVG nor this site changes the profile radar. New eligible issues, PRs and code reviews can eventually alter its proportions, depending on GitHub's contribution criteria and the existing year's activity.

The artistic constraint is that those public contributions must stand on their own. No duplicate issues, fabricated reviews, artificial conversations, manufactured commit histories, or PRs created just to occupy an axis. The documentation, code and reciprocal labour are part of the piece.

The aim is not to reach four equal quarters. It is to discover what a public system decides to count, and what it leaves out.

## Technical score

Let the four nonnegative channel inputs be `v = [commit, pull, issue, review]`. The interactive score normalizes them:

`share_i = v_i / sum(v) × 100` (or all zeros if the sum is zero).

Each arm has a cardinal direction, plus a small nonzero visual core for zero-value axes. Echo polygons are scaled and subtly rotated, representing the instability of reading a person as a chart. Oscillator gains follow normalized shares; frequencies are derived from a four-note original harmonic arrangement in the low register. All inputs are local and reversible.

GitHub's own formula, time windows, filtering and eligibility may differ. The model here is **explicitly illustrative**, not a claim of GitHub parity.
